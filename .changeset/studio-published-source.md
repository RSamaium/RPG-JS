New `published` runtime mode for `provideStudioGame` (and `configureStudioGameRuntime`): the game reads the bundle of a published snapshot (`bundleBasePath`, a path or the complete URL such as `<api>/published/<projectId>`), keeps its project id, and resolves the events of the maps from the `events.json` of the bundle whatever the project id. A page opened with `?editor` or `?preview` still reads the draft online, with an optional preview token sent in the `x-studio-preview-token` header (`previewToken`, or `?preview=<token>`, kept for the tab and taken off the address bar). `GameDataProvider.getPlugins(projectId?)` reads `plugins.json` of a bundle or `/game/plugins` of the API. With `provideStudioGame({ scripts })` (the `ScriptService` of `@rpgjs/script`) the plugins are installed when the server starts (`<pluginId>/<scriptName>`) and kept in step with the data: read again, replaced or uninstalled when the data of the project is invalidated. `installPlugins` hands the same list to another interpreter. In an MMORPG the plugins come with the published version (`plugins` of the map update): they are installed or replaced in every room together with its maps, and a room that restarts reads the version it runs.
